# Models

## 1. Introduction and Goals

A model declares the records an application stores: the stored fields, the identity that names a record on every runtime, and the unique constraints the local database enforces.

## 3. Context and Scope

- Source: `model Name { field Type[]? … @@id(a, b) @@unique(x, y) @@version(n) }`.
- Descriptor: `{name, version, identity, fields, relations, unique}`; a field is `{name, type, nullable}` plus an optional `createDefault` from `@default`. Fields typed as another model are not stored fields; they become [Relations](relations.md).
- Consumers: [Client / Storage](../client/storage/README.md) creates one table per model plus a before-image twin; [Compiler / Generate](../compiler/generate.md) emits the `Name`, `NameIdentity`, `NamePatch` and `NameCreate` types; the server keys loaders by model name ([Backend interface](../server/backend-interface.md)).

## 5. Building Block View

- **Fields.** `name Type[]?` with at most one each of the directives `@reference`, `@inverse`, `@requires`, `@default(…)` and `@deprecated(reason: "…")` (the reason optional). Names are ASCII identifiers and unique within the model.
- **Identity.** Exactly one `@@id(...)` naming non-nullable scalar fields. Its order is the primary-key order. A model without `@@id` is invalid.
- **Unique constraints.** Any number of `@@unique(fields)` over existing, distinct fields. The client creates a unique index per constraint; the server never sees them.
- **Version.** `@@version(n)` names the read contract: the record structure a loader of that version returns. It defaults to 1, must be a positive safe integer, and is independent of mutation versions and of record stamps. The compiler keeps every published version's `{name, version, identity, fields, enums}` in `history/models.json` beside the schema ([Generate](../compiler/generate.md#9-architecture-decisions)); the enums are copied as they were, so a later value never reaches an older contract. Within one version the only accepted change is an added nullable field; a required field, a renamed, removed or retyped field, or any change to a used enum's values needs a higher version, and the older snapshot stays as published. An identity change is refused at every version. The client's embedded schema carries the current version of each model; the retained contracts go to the backend ([Typed API / Server](../sdks/typed-api/server.md#9-architecture-decisions)).
- **Names.** Models and enums share one namespace. Model names starting with `axton_` (framework tables) or `sqlite_` (SQLite's own reserved prefix) are refused; the comparison ignores case because SQLite table names do. A model or enum may not take a name the generated client or its runtime declares (`GENERATED_NAMES` in [compiler/validate.rs](../../../../crates/compiler/src/validate.rs)), since both would share the generated file's top level.
- **Creation defaults.** `@default(value)` on a stored scalar or enum field: a string, number, `true`/`false` or enum member literal normalized by the field's rules, `uuid()` on String/UUID (lowercase v4) or `now()` on DateTime (client UTC, milliseconds). It becomes `createDefault` (`{kind:"literal",value}`, `{kind:"uuid"}`, `{kind:"now"}`), which core validates against the field type; the internal `default` used by older reconciliation paths is separate and never set from source. Only an omitted field of a fresh create receives it; see section 9. The client fills it in `client/defaults.rs`.
- **Record key.** The identity object with exactly the identity fields, normalized; its canonical encoding is the record's key in every table and message ([Protocol / Common](../protocol/common.md)).
- **State and patch shapes.** Received states must carry every non-identity field or a nullable default; patches may name only known non-identity fields; identity is immutable ([Protocol / Common](../protocol/common.md)).

Code: parsing in [compiler/parse.rs](../../../../crates/compiler/src/parse.rs); name, identity and unique checks in [compiler/validate.rs](../../../../crates/compiler/src/validate.rs); version history in [compiler/history.rs](../../../../crates/compiler/src/history.rs) (`reconcile_model_history`); descriptor rules and record keys in [core/schema.rs](../../../../crates/core/src/schema.rs); tables and indexes in [client/ddl.rs](../../../../crates/client/src/ddl.rs).

## 9. Architecture Decisions

**Model versions ([#91](https://github.com/zanminwang/axton/issues/91)).** Declare the read contract version on the model with `@@version(n)`, defaulting to 1, independently of mutation versions and record stamps. Compatible changes keep the version; breaking changes retain the old definition and loader alongside the new one. Read compatibility needs its own rules: adding a field or enum value is not automatically safe for an old client. The declaration, the history and the field-evolution rules below are implemented in the compiler (section 5), loaders are registered and dispatched per version ([Typed API / Server](../sdks/typed-api/server.md#9-architecture-decisions)), and the client declares the versions it reads on every pull and subscribe ([Protocol / Pull](../protocol/pull.md)). Per-read handling of an undeclared model is [#95](https://github.com/zanminwang/axton/issues/95); identity, relation and constraint changes have no agreed rule, so the compiler refuses an identity change at every version rather than deciding one.

**Adding a nullable field — agreed read contract.** Adding an ordinary nullable stored field, without changing identity or constraints, keeps the model version. An older client ignores the unknown extra field while applying the fields it recognizes; a newer client reads a missing nullable field as `null`. For example, adding `description String?` preserves reads of `Task {id, title}`. The local SQLite layout still needs the new column ([Reconciliation](../client/storage/reconciliation.md)). This permits ignoring extra fields, not wrong types in known fields; handling malformed records remains owned by [#51](https://github.com/zanminwang/axton/issues/51). This decision does not settle mutation-input compatibility or cache refresh after previously ignoring a field.

**Adding a required field — agreed read contract.** A new non-nullable stored field requires a model version bump: older records lack the required value. The new loader supplies valid values; AXTON must not invent a value. Locally, the client detects the change at open and rebuilds its database beside the old one ([Reconciliation](../client/storage/reconciliation.md), [#20](https://github.com/zanminwang/axton/issues/20)).

**Adding a returned enum value — agreed read contract.** Expanding an enum used by a model's existing read contract requires a new model version: an older client may recognize the field but cannot interpret the new value. For example, adding `archived` to `open | closed` requires retaining the old record definition and loader. The application implements the old loader's conversion into values allowed by that old contract; the framework does not guess a fallback or forward the new value to old readers. This is an output rule, not a change to mutation-input enum compatibility.

**Renaming, removing or changing a field's type — agreed read contract.** Each is a breaking change and requires a model version bump. While supporting the old version, retain its definition and loader, returning the old field names and types. The application supplies the mapping or conversion; the compiler must not infer a rename or silently coerce values. This rule covers the public record contract, not permission to migrate identities, relations or persisted client data automatically.

**Creation defaults are create-only client policy ([#27](https://github.com/zanminwang/axton/issues/27)).** Every source `@default`, constants included, fills only a field that a fresh create omits: a local `create` (inside a transaction too), a fresh low-level enqueue and the `Model.create` operands of durable and direct Mutations, including optional (when present) and list (per item) operands. The client materializes the values once, in `client/defaults.rs`, before strict normalization, record-key construction, binding checks, persistence or dispatch; optimism, the persisted intent, frozen bytes and the direct request all carry those concrete values, and retries, reopen, freezing, replay and settlement never regenerate them. For a Mutation the current Model's policy applies only to fields of the operation's retained input contract, so a default is never injected into a version that predates its field. An explicit value wins; an explicit null stays null for a nullable field and is refused for a required one. Updates, deletes, identity lookups, Loader records, incoming authority, server decoding and migration never evaluate a default: omission in an update means no change, and a Loader record missing a required field stays malformed. `now()` is the device's clock, not a trusted server time. A local `create` still returns nothing; generated values are visible through reads, watch and declared Mutation outputs, and callers needing an identity first supply it explicitly.

Creation policy is not part of any backend contract. `createDefault` is projected out of retained Model read snapshots, `resultModels` and operation-input snapshots, and history compares shapes without it, so adding, changing or removing a default needs no Model or Mutation version bump and rewrites no stored row, queued argument or frozen request. Adding a required field is still a read-contract change that needs a version bump even with a default, and a default never fills historical records, locally or on the server.

A field marked `@deprecated` keeps its place in every contract; the notice is generated code only ([Mutations](mutations.md#9-architecture-decisions)). See [Typed API / Server](../sdks/typed-api/server.md#9-architecture-decisions) for loader registration and [Generate](../compiler/generate.md#9-architecture-decisions) for history storage. Contract history does not migrate existing local records; the client applies the same compatibility rule at open, shared through `Schema::compatibility` in `axton-core`, and rebuilds an incompatible replica ([Reconciliation](../client/storage/reconciliation.md)).

## 10. Quality Requirements

- An invalid identity (nullable, non-scalar, missing, duplicated) is refused at compile time. Evidence: [compiler/tests/compiler.rs](../../../../crates/compiler/tests/compiler.rs) `rejects_invalid_identity`, `schema_and_mutations`.
- A unique constraint holds atomically within a local transaction: a violating write rolls back only its own savepoint (guarantee L3). Evidence: [sqlite/tests/client.rs](../../../../crates/sqlite/tests/client.rs) `declared_unique_constraint_is_atomic`.
- A reserved model name is refused at compile time at its declaration and again at load time; names that merely contain the words stay valid. Evidence: [compiler/tests/compiler.rs](../../../../crates/compiler/tests/compiler.rs) `rejects_reserved_model_names_at_the_declaration`, `rejects_model_and_enum_names_the_generated_client_uses`; [core/tests/contracts.rs](../../../../crates/core/tests/contracts.rs) `field_default_and_record_stamp_round_trip_and_axton_prefix_is_rejected`.
- Duplicate model or enum names, a missing `@@id` and an identity over a nullable or list field are refused at the declaration. Evidence: `semantic_errors_report_the_offending_declaration`.
- Creation defaults: each supported kind compiles to normalized `createDefault` and invalid ones are refused at the declaration; the client fills only omitted fields of fresh creates, once, on local create, low-level enqueue and both Mutation routes (optional and list operands, retained-contract restriction), keeps explicit values and nulls, rolls back with its transaction, and never fills updates, Loader records or server decoding; values survive reopen and replay; a default-only change keeps every retained version and opens the local database in place, while a new required field still needs a bump and rebuilds. Evidence: [compiler/tests/defaults.rs](../../../../crates/compiler/tests/defaults.rs); [sqlite/tests/defaults.rs](../../../../crates/sqlite/tests/defaults.rs); [compiler/tests/history.rs](../../../../crates/compiler/tests/history.rs) `default_only_changes_keep_retained_versions_and_required_fields_still_break`; [core/tests/compatibility.rs](../../../../crates/core/tests/compatibility.rs) `creation_defaults_are_policy_not_storage_shape`; against PostgreSQL through both handler routes in [action.test.mts](../../../../integration/action-e2e/action.test.mts) `create defaults are generated once by the client and reach both routes unchanged`.
- An omitted version is version 1; an added nullable field keeps the version; a required field, a renamed, removed or retyped field and a new enum value each need a higher version, after which the old contract and its enum values stay as published; an identity change is refused at any version; a version cannot decrease and a retained model cannot disappear. Evidence: [compiler/tests/history.rs](../../../../crates/compiler/tests/history.rs) `models::*`; [compiler/tests/cli.rs](../../../../crates/compiler/tests/cli.rs) `cli_retains_model_history_and_refuses_a_breaking_read_change_without_a_bump`. Executed 2026-09-15: `cargo test -p axton-compiler --locked` (37 passed).

## 11. Risks and Technical Debt

- **Accepted limitation:** `now()` uses the client clock and `uuid()` a client generator; neither is a trusted server value, and multiple `now()` fields of one create need not share an instant.
- **Accepted limitation:** creation defaults never backfill. A new required field always rebuilds the local database ([Reconciliation](../client/storage/reconciliation.md)) and needs a model version bump; historical values come from the application's loaders.
- **Accepted limitation:** unique constraints and identities are enforced on the client only; the application's database schema is authoritative on the server.
