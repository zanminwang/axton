# Rust-owned Client Runtime Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement the four checkpoints in one draft PR. Steps use checkbox (`- [ ]`) syntax for tracking. Use implementation subagents only when explicitly authorized; the owner reviews checkpoint evidence and the final PR.

**Goal:** Make Rust own complete client tasks and local transaction scheduling while SDKs expose typed APIs and execute platform effects.

**Architecture:** A generic Rust runtime owns task/effect/transaction state and reuses the existing client engines. A native per-client actor owns SQLite; a central SDK Bridge registers waiters, executes requested I/O/callbacks and delivers Rust events. Preserve current public behavior and backend protocol.

**Tech Stack:** Rust, serde JSON, SQLite, N-API, Dart FFI, Expo/Swift React Native adapter, TypeScript and Dart typed interfaces.

## Global constraints

- Implement the [design](../specs/2026-09-25-134-rust-runtime-design.md) and preserve the owning [guarantees](../../engineering/guarantees.md).
- One isolated `codex/` branch and one draft PR; four reviewed checkpoints, one final merge. No implementation of #17, #144, #152 or #59 in this PR.
- Start from current main with the reviewed planning commits; retain #162/#163 if already merged, and integrate later arrivals before final review. Do not overwrite their worker/host fixes.
- Rust owns task progression; SDK maps and platform resources are adapters. A submitted command's admission acknowledgement is not task completion.
- Complete required local writes before success events. Keep Call submission versus final Call outcome distinct, and keep Query result snapshots unchanged.
- No global lock during database work or host callback waiting. Ordinary reads cannot enter another task's active transaction.
- No new persistent inbox, storage migration, backend version bump or direct-call replay policy solely for this refactor.
- SDK local callback return values can be non-JSON language objects; carry callback completion through Rust but retain the original value in SDK memory.
- Use targeted tests for each checkpoint and the full repository gate after integration. Do not repeatedly run the full gate absent new changes or unresolved failures.

## Checkpoint 1: Executable bridge and transaction ownership

**Deliverable:** A real Rust-owned client can open, execute local tasks, run a host transaction callback and close through the new bridge on supported native carriers. The old adapter can remain during the draft only.

**Internal interfaces:** `ClientRuntime<S>::receive(input, now, entropy)` accepts typed inputs and advances nonblocking state; `step(now, entropy)` runs one eligible local unit; `take_events()` drains committed outputs. The actor owns the runtime; the host sees only `submit`, `drain`, and wake notifications. Use the spec's JSON envelopes and unique string IDs. The precise Rust return types should expose errors separately from the queued public completion events and must not return `Client` references to a carrier.

- [ ] Read the owning architecture, inspect `RuntimeHost::call`, all three carriers and SDK transaction tests, and record baseline results following [running tests](../../engineering/testing/running.md). Add the single draft PR and link the spec/plan once there is reviewable implementation.
- [ ] Add a deterministic runtime fixture backed by a real temporary `SqliteStore`. It constructs `ClientRuntime` with known clock/entropy, admits inputs, calls `step`, and drains events. Test two independent request IDs and reverse completion order; duplicate IDs cannot execute twice; a failure completes only its waiter. Add JSON envelope fixtures decoded by Rust and both SDKs.
- [ ] Implement protocol, task table and the central SDK maps. Register before admission, remove before user callbacks, and reject on admission failure. The dispatcher creates a Call handle synchronously during acceptance decoding before later call outcome events. Keep observer exceptions outside engine outcomes.
- [ ] Implement the per-client actor opening SQLite on its own thread. Registry locks only clone handles/senders or update registry entries; no SQLite or callback wait occurs under them. Implement an event outbox with a wake/drain/recheck handshake. Test publication just before/during/after drain and detach; every completion is delivered exactly once.
- [ ] Wire Node wake through N-API, Dart through a cross-thread listener callback, and RN through the native event adapter. Allocate wake registration before background open can finish. Wake callbacks carry an opaque token, not borrowed JSON pointers. Use owned drain buffers and free them once. Test open failure and close/detach before freeing callback contexts. Never use a blocking event receive on the same carrier path needed to submit callback answers.
- [ ] Add transaction capability tests: a normal read admitted while another callback owns the transaction waits; a matching `tx` command runs; wrong/stale token fails without joining; nested savepoint ownership cannot overlap; callback failure rolls back; close during callback rolls back and releases queued waiters. Use the following scenario as an acceptance trace:

```text
submit transaction request 1 -> callback effect with tx A
submit ordinary read request 2 -> no completion while tx A is open
submit tx A write request 3 -> request 3 succeeds inside tx A
submit wrong-token read request 4 -> request 4 fails, tx A unchanged
return callback success -> commit -> complete request 1 -> execute request 2
```

- [ ] Adapt public transaction/savepoint wrappers to callback effects and scoped tokens. Preserve SDK async-context guards and non-serializable callback return values; Rust owns scope completion and admission. Introduce no downlink hook registration yet.
- [ ] Run `cargo test -p axton-binding --test runtime --locked`, `cargo test -p axton-sqlite --test runtime --locked`, relevant existing session/transaction suites, and the new TS/Dart bridge suites after rebuilding artifacts. Prove independent client B completes while client A is parked in a callback using synchronization barriers, not latency guesses. Review checkpoint 1 for deadlocks, callback lifetime and global-lock regressions; resolve findings and commit.

## Checkpoint 2: Complete operation lifecycles in Rust

**Deliverable:** Every local/remote data path uses the runtime; required Model storage commits before success. SDKs no longer orchestrate a Query as prepare/send/apply.

- [ ] Add direct Query and Mutation tasks that prepare existing protocol bytes, allocate an HTTP effect, wait without a writer, then validate/apply using existing `apply_action_response` machinery. An HTTP effect result is a fact, not a command from SDK to choose a specific next engine step. Completion data comes from the response snapshot, not `client.read`.
- [ ] Test an HTTP effect held outstanding while a local write and an unrelated Channel page commit. Then resolve it and assert the public success event observes committed Models. Inject SQLite commit failure: no successful task event or changed snapshot may escape. Test `store:false`, no-record results and snapshot-versus-pending-optimism behavior.
- [ ] Integrate durable acceptance and the existing `SyncCycle`: acceptance completion returns the Call identity only after canonical intent/optimism commit; receipt handling emits `callCompleted` after its settlement commit. Keep a single frozen batch in flight as today. Ensure final outcomes cannot outrun Call registration and work with no subscribed Channel.
- [ ] Integrate `DownlinkWorker` as an existing component, retaining its page queue, gap recovery and Bootstrap request slot. Map existing worker actions to runtime effects; route their responses back with lifetime fences. Replace host-owned pump policy with Rust scheduling, retaining only platform wake delivery. Preserve one-local-unit fairness and the existing barrier settlement exception.
- [ ] Bring prerequisites into the same callback-effect mechanism without moving user code into Rust or holding a write transaction across prerequisite I/O. Preserve the existing Rust task selection and completion contracts.
- [ ] Test mixed receipt/direct/page ordering, duplicate and stale effects, Bootstrap progress beside live traffic, old responses after close/rebuild, and preserved #162/#163 scenarios. Use the existing `bootstrap_worker`, `downlink_worker`, action/store and settlement suites as regression evidence in addition to new runtime tests.
- [ ] Run focused Rust and language action/subscription/once suites, rebuild native artifacts, and run applicable end-to-end scenarios. Review checkpoint 2 for commit-before-delivery, effect ownership and unintentional protocol/retry changes. Record actual commands and findings, fix them, then commit.

## Checkpoint 3: Shared lifecycle, status and observation rules

**Deliverable:** SDKs dispatch language-level objects but do not decide retry, task completion, Bootstrap status, Query flight or watcher re-query policy.

- [ ] Move direct-call deadlines, availability/lifecycle transitions and authentication refresh coordination into Rust. Timer firing and auth responses are correlated effects. Preserve the existing timeout and retry behavior; do not retry an unknown direct execution simply because the architecture changed. Test auth-refresh joins, timeout versus simultaneous response, pause/close and late failure events with a fake clock.
- [ ] Replace SDK Query-flight state machines with task IDs joined to the Rust flight. Cached tasks complete without reapplying Model authority; fetched tasks write authority/cache once and complete every joined task with separately decoded result values. Test invalidation/refresh fences, failed fetch cleanup, offline hit/miss and close with joined callers.
- [ ] Move Subscription connection/initialization/Bootstrap projection and run-supersession decisions into Rust observers. SDK handles retain language identity and observers only. Test initialized/uninitialized registration, reconnect, unsubscribe/re-register, retry replacing a run and reopen resumption. Compare snapshots and errors with the existing public contract.
- [ ] Move local watch query registration/re-execution/equality decisions to Rust. Preserve initial emission, committed-state reads, suppression of equal results, unsubscribe, close and callback-error isolation. Start with existing coarse change evidence rather than adding #16 query-dependency features. Test no re-query decisions remain in TS/Dart, and no uncommitted callback writes are visible to unrelated observers.
- [ ] Implement priority close and carrier failure cleanup. Every live request is completed or rejected, durable accepted calls remain persisted, effects are fenced/cancelled, callbacks cannot outlive their transaction, and the wake sink is detached before being freed. Rebuild invalidates old registrations and replica-bound tasks without recycling IDs or losing #162/#163 behavior.
- [ ] Run native task/observer lifecycle tests, TS/Dart API suites and RN carrier tests. Review checkpoint 3 for remaining duplicated policy and changed error meanings; retain SDK Promise/WeakRef/async-context code where it is language adaptation. Fix findings and commit.
