# Models

## 1. Introduction and Goals

A model declares the records an application stores: the stored fields, the identity that names a record on every runtime, and the unique constraints the local database enforces.

## 3. Context and Scope

- Source: `abstract model Fields { … }` and `model Name extends Fields { field Type[]? … @@id(a, b) @@unique(x, y) @@version(n) @@bootstrap }`; `extends` and `@@bootstrap` are optional.
- Descriptor: `{name, version, identity, fields, relations, unique, bootstrap?}`; a field is `{name, type, nullable}` plus an optional `createDefault` from `@default`. Fields typed as another model are not stored fields; they become [Relations](relations.md).
- Consumers: [Client / Storage](../client/storage/README.md) creates one table per model and retained before-image state; [Compiler / Generate](../compiler/generate.md) emits the `Name`, `NameIdentity`, `NamePatch` and `NameCreate` types; the server keys loaders by model name ([Backend interface](../server/backend-interface.md)).

## 5. Building Block View

- **Shared fields.** `abstract model` declares reusable fields and may extend one other abstract model. A concrete model may extend one abstract parent. Inheritance copies complete field declarations, including defaults, prerequisites, deprecation and relation annotations, then validates them in each concrete model. Cycles, duplicate fields, concrete parents and relations targeting abstract models are refused. Abstract models declare no model-level directives, identity, table or generated Model facade. Each concrete model declares its own `@@id`, constraints and version.
- **Bootstrap selection.** `@@bootstrap` emits `bootstrap: true` on a concrete descriptor; omission means false. This marks the type for initial history selection and imposes no restriction on later Stream records. It is metadata, not a stored field or a read-contract member. Finite Bootstrap selects these Models under the active retained materialization ([the sync protocol](../protocols/wire.md)).

- **Fields.** `name Type[]?` with at most one each of the directives `@reference`, `@inverse`, `@requires`, `@default(…)` and `@deprecated(reason: "…")` (the reason optional). Names are ASCII identifiers and unique within the model.
- **Identity.** Exactly one `@@id(...)` naming non-nullable scalar fields. Its order is the primary-key order. A model without `@@id` is invalid.
- **Unique constraints.** Any number of `@@unique(fields)` over existing, distinct fields. The client creates a unique index per constraint; server business enforcement belongs to the application database, while finite authority grouping uses retained constraint metadata.
- **Version.** `@@version(n)` names the read contract: the record structure a loader of that version returns. It defaults to 1, must be a positive safe integer, and is independent of mutation versions and of Stream cursor progress. The compiler keeps every published version's `{name, version, identity, fields, enums}` in `history/models.json` beside the schema ([Generate](../compiler/generate.md#9-architecture-decisions)); the enums are copied as they were, so a later value never reaches an older contract. Within one version the only accepted change is an added nullable field; a required field, a renamed, removed or retyped field, or any change to a used enum's values needs a higher version, and the older snapshot stays as published. An identity change is refused at every version. The client's embedded schema carries the current version of each model; the retained contracts go to the backend ([Typed API / Server](../backend-sdk/api.md#9-architecture-decisions)).
- **Names.** Models and enums share one namespace. Model names starting with `axton_` (framework tables) or `sqlite_` (SQLite's own reserved prefix) are refused; the comparison ignores case because SQLite table names do. A model or enum may not take a name the generated client or its runtime declares, or a type name the generated backend declares (`GENERATED_NAMES` and `GENERATED_BACKEND_NAMES` in [compiler/validate.rs](../../../../crates/compiler/src/validate.rs)), since both would share the generated file's top level. The generated backend addresses Models by lower-first accessors on callable `RecordDeclaration` namespaces (`track` and `invalidate`). Two Models may not share an accessor (`Todo` and `todo`); declaration verbs do not reserve Model accessors such as `add` or `remove`.
- **Creation defaults.** `@default(value)` on a stored scalar or enum field: a string, number, `true`/`false` or enum member literal normalized by the field's rules, `uuid()` on String/UUID (lowercase v4) or `now()` on DateTime (client UTC, milliseconds). It becomes `createDefault` (`{kind:"literal",value}`, `{kind:"uuid"}`, `{kind:"now"}`), which core validates against the field type; the internal `default` used by older reconciliation paths is separate and never set from source. Only an omitted field of a fresh create receives it; see section 9. The client fills it in `client/defaults.rs`.
- **Record key.** The identity object with exactly the identity fields, normalized; its canonical encoding is the record's key in every table and message ([Sync](../protocols/wire.md)).
- **State and patch shapes.** Received states must carry every non-identity field or a nullable default; patches may name only known non-identity fields; identity is immutable ([Sync](../protocols/wire.md)).

Code: parsing in [compiler/parse.rs](../../../../crates/compiler/src/parse.rs); name, identity and unique checks in [compiler/validate.rs](../../../../crates/compiler/src/validate.rs); version history in [compiler/history.rs](../../../../crates/compiler/src/history.rs) (`reconcile_model_history`); descriptor rules and record keys in [core/schema.rs](../../../../crates/core/src/schema.rs); tables and indexes in [client/ddl.rs](../../../../crates/client/src/ddl.rs).

## 9. Architecture Decisions

**Model versions ([#91](https://github.com/zanminwang/axton/issues/91)).** Declare the read contract version on the model with `@@version(n)`, defaulting to 1, independently of Mutation versions and Stream cursors. Compatible changes keep the version; breaking changes retain the old definition and loader alongside the new one. Read compatibility needs its own rules: adding a field or enum value is not automatically safe for an old client. The declaration, the history and the field-evolution rules below are implemented in the compiler (section 5), loaders are registered and dispatched per version ([Typed API / Server](../backend-sdk/api.md#9-architecture-decisions)), and the materialization identifies the Model contracts the client reads ([the sync protocol](../protocols/wire.md)). Per-read handling of an undeclared model is [#95](https://github.com/zanminwang/axton/issues/95); identity, relation and constraint changes have no agreed rule, so the compiler refuses an identity change at every version rather than deciding one.

**Adding a nullable field — agreed read contract.** Adding an ordinary nullable stored field, without changing identity or constraints, keeps the model version. An older client ignores the unknown extra field while applying the fields it recognizes; a newer client reads a missing nullable field as `null`. For example, adding `description String?` preserves reads of `Task {id, title}`. The local SQLite layout still needs the new column ([Reconciliation](../client/storage/reconciliation.md)). This permits ignoring extra fields, not wrong types in known fields; handling malformed records remains owned by [#51](https://github.com/zanminwang/axton/issues/51). This decision does not settle mutation-input compatibility or cache refresh after previously ignoring a field.

**Adding a required field — agreed read contract.** A new non-nullable stored field requires a model version bump: older records lack the required value. The new loader supplies valid values; AXTON must not invent a value. Locally, open refuses an unsupported storage change without modifying the file. Choose a separate fresh file or an explicit supported reset after accounting for pending work ([Reconciliation](../client/storage/reconciliation.md), [#20](https://github.com/zanminwang/axton/issues/20)).

**Adding a returned enum value — agreed read contract.** Expanding an enum used by a model's existing read contract requires a new model version: an older client may recognize the field but cannot interpret the new value. For example, adding `archived` to `open | closed` requires retaining the old record definition and loader. The application implements the old loader's conversion into values allowed by that old contract; the framework does not guess a fallback or forward the new value to old readers. This is an output rule, not a change to mutation-input enum compatibility.

**Renaming, removing or changing a field's type — agreed read contract.** Each is a breaking change and requires a model version bump. While supporting the old version, retain its definition and loader, returning the old field names and types. The application supplies the mapping or conversion; the compiler must not infer a rename or silently coerce values. This rule covers the public record contract, not permission to migrate identities, relations or persisted client data automatically.

**Creation defaults are create-only client policy ([#27](https://github.com/zanminwang/axton/issues/27)).** Every source `@default`, constants included, fills only a field that a fresh create omits: a local `create` (inside a transaction too), the `Model.create` operands of named Mutations, including optional (when present) and list (per item) operands. The client fills the values once, in `client/defaults.rs`, before strict normalization, record-key construction, binding checks, persistence or dispatch; optimism, the persisted intent, frozen bytes all carry those concrete values, and retries, reopen, freezing, replay and settlement never regenerate them. For a Mutation the current Model's policy applies only to fields the operation's retained input contract declares with the same type, so a default is never injected into a version that predates or reshaped its field. An explicit value wins; an explicit null stays null for a nullable field and is refused for a required one. Updates, deletes, identity lookups, Loader records, incoming authority, server decoding and migration never evaluate a default: omission in an update means no change, and a Loader record missing a required field stays malformed. `now()` is the device's clock, not a trusted server time. A local `create` still returns nothing; generated values are visible through reads, watch and declared Mutation outputs, and callers needing an identity first supply it explicitly.

Creation policy is not part of any backend contract. `createDefault` is projected out of retained Model read snapshots, `resultModels` and operation-input snapshots, and history compares shapes without it, so adding, changing or removing a default needs no Model or Mutation version bump and rewrites no stored row, queued argument or frozen request. Adding a required field is still a read-contract change that needs a version bump even with a default, and a default never fills historical records, locally or on the server.

A field marked `@deprecated` keeps its place in every contract; the notice is generated code only ([Mutations](mutations.md#9-architecture-decisions)). See [Typed API / Server](../backend-sdk/api.md#9-architecture-decisions) for loader registration and [Generate](../compiler/generate.md#9-architecture-decisions) for history storage. Contract history does not migrate existing local records; the client applies the same compatibility rule at open, shared through `Schema::compatibility` in `axton-core`, and refuses incompatible changes intact ([Reconciliation](../client/storage/reconciliation.md)).

## 11. Risks and Technical Debt

- **Accepted limitation:** `now()` uses the client clock and `uuid()` a client generator; neither is a trusted server value, and multiple `now()` fields of one create need not share an instant.
- **Accepted limitation:** creation defaults never backfill. A new required field without a storage default resets the Model at local open ([Reconciliation](../client/storage/reconciliation.md)) and needs a model version bump; historical values come from the application's loaders.
- **Accepted limitation:** unique constraints and identities are enforced on the client only; the application's database schema is authoritative on the server.
