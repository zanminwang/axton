# Query once result snapshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persist and reuse complete direct Query results on explicit once calls, with refresh and invalidation while preserving current Models.

**Architecture:** Rust owns canonical keys, persistent snapshots, generation fencing and active flights. SDKs execute existing direct transport and fan out raw completions before decoding each caller's output independently. Successful cache write and authority application share one local transaction.

**Tech Stack:** Rust client/core/native bindings, SQLite, TypeScript/React Native and Dart, existing direct-call integration hosts.

## Global constraints

Follow the [spec](../specs/2026-09-25-158-query-once-design.md) and [#158](https://github.com/zanminwang/axton/issues/158). This assignment is documentation only. User assigns implementation separately. Default Query behavior remains fresh; once/refresh are direct Query-only. Complete snapshots are persisted even with store:false. Hits never write Models. Cache is database/account-scoped; no token-derived identity claims. No TTL, query membership inference, schema annotation, new endpoint or queued-Query cache lifecycle. Preserve #157 and integrate #27/#151 if they merge first.

## Task 2: Rust request coordinator and atomic completion

**Files:** `crates/client/src/query_cache.rs`, `actions.rs`, `lib.rs`; tests `crates/sqlite/tests/query_cache.rs`, existing `actions.rs`.

**Interfaces:** Implement begin_query_once -> Cached/Join/Fetch, finish_query_once, fail_query_once and invalidate_query_once as specified. Active flights retain the exact direct request and generation, indexed by flight ID and a separate (key,generation) join index; old and new generations may coexist. They are not durable queue rows.

- [ ] Write state-machine tests for miss coalescing, refresh coalescing, hit while refreshing, failed refresh retaining old result, failed miss retry and independent default requests.
- [ ] Begin validates transaction/kind/args/options, checks committed snapshot unless refresh, and returns a matching active flight or records a new prepared request. Validate refresh requires once. No network availability requirement on a hit.
- [ ] Refactor the existing direct-response application just enough to share its validation and write transaction with cache completion:

```text
validated response + matching flight
  -> apply existing authority/report rules
  -> if success and generation still matches: save canonical result
  -> commit
  -> publish completion; retire only this flight
```

  Plain results with zero authority records still require a cache transaction. A failed commit leaves neither a new cache snapshot nor partial authority. Cache hit never invokes this application path.
- [ ] Add invalidation race tests: old flight resolves observers but cannot restore cache; new generation survives old completion/failure. Use the existing stamped-authority rules for any old network response.
- [ ] Reject malformed cached results through output validation; invalidate and miss without swallowing database errors. Verify no stale cache Model data is reapplied after a Scope update/local edit.
- [ ] Run core/client/sqlite tests and commit coordinator behavior.
