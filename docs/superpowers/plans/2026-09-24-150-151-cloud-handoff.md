## Decisions to preserve

1. Existing subscriptions already persist. #150 changes new-subscription initialization and adds the observable reusable handle; it does not rebuild persistence from scratch.
2. `await client.scopes.subscribe(scope)` waits for local intent commit and works offline. The first handshake atomically fills nullable `starting_cursor` and live `cursor` with the acknowledged head. Null is distinct from zero. The subscription origin stays fixed; reconnect resumes committed progress.
3. Only desired Scopes join live delivery and automatic delta requests. Mixed existing/uninitialized subscriptions are handled separately. Existing A at 80 with acknowledged head 100 catches up; new B at acknowledged 200 starts at 200; absent C is excluded.
4. Keep server post-listener drain, client reconnect catch-up, stream-gap recovery and overflow recovery. Remove only implicit history loading on new subscribe. A page 120→125 can apply at local 120; 124→125 must wait for delta repair. Compaction makes gaps between individual record positions normal.
5. Bootstrap is bound to a durable subscription. Separate B advances from zero to origin S; live L advances independently after S. A record republished from 40 to 120 with S=100 belongs to live delivery, so no immutable `first_cursor` or identity-pagination design is needed.
6. On the last historical page, persist its current server head H. Resolve Bootstrap after B=S and L>=H have committed. H stays fixed while waiting. Never advance live progress artificially or chase the latest head forever.
7. Use the existing `/sync/pull` route. Rust `process_pull` dispatches ordinary versus Bootstrap requests for all callers. Reuse scans, repeatable-read host transaction, Loader normalization and authority stamp application. Bootstrap bypasses the ordinary delivery-cursor gate but not stamp/pending-replay rules.
8. `subscription.bootstrap()` eagerly registers durable work; awaiting observes completion. Repeated calls share the run; completed valid state returns locally even offline. Close rejects local waiters but retains work. Unsubscribe removes that subscription's work and preserves local Models/stamps/pending Actions.
9. Historical Loader/apply failures reject that run without advancing its page marker; successful authority from that page remains. Explicit retry revisits the saved marker. ReadFailed/Skipped/Conflict are coverage failures; Diverged pending-Action reports are observable without invalidating successfully loaded authority. Live D7 failures remain reported and do not become successful authority merely because cursor progress/completion advances. Completion is delivery coverage, not an unconditional all-reads-succeeded or global-snapshot claim.
10. Scope continues to mean publication-based delivery. No current-membership inference (#140), eviction implementation (#139), in-place WebSocket membership protocol (#144), comprehensive rename (#152), or record/Scope+Model loading (#153/#154). Generated `scopes` is the new facade; existing names delegate to the same runtime until #152.
