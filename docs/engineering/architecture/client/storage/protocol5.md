# Protocol 5 durable storage

Protocol 5 storage owns one physical file, Client and Stream. Rust transfer orchestration owns delivery validation, completeness and post-commit notifications; the SDKs execute its effects. See the [protocol owner](../../protocols/sync.md) and [fresh-file adoption limits](../../../protocol5-adoption.md).

`axton_store` owns the file identity, one Stream, enabled and desired read contexts, the next Mutation and local-operation sequences, the last acknowledged Batch, and S/B/C. A handshake initializes S and C=S; B remains absent until the final Bootstrap unit commits. Format and Stream admission precede schema changes. `SqliteStore::open_exclusive05` locks the physical file before admission and WAL initialization. For a nonempty file, admission reads a temporary copy of the database and any matching WAL while holding that lock. Refusal leaves the original database, WAL and SHM bytes untouched. Copy and open have a file-size-dependent cost; temporary files are removed on success and failure.

`axton_mutation_queue` is the lifecycle owner. Its operation table retains each supplied input argument or Model slot row, with an explicit input path. Null input paths are local companions and derived cascades. Omitted optional slots, explicit null and empty arrays remain distinct. Reconstruction uses the retained schema artifact and applies no new defaults. Assigned input and Batch membership are immutable; later derived cascades may extend local effects without changing the request.

A schema artifact fingerprint retains the complete compiled schema, including Action input snapshots and array order. It is distinct from the read materialization identity, whose canonical Model read descriptors ignore field order. Compatible reorder keeps existing queued artifacts and frozen request bytes. A changed read materialization is persisted as desired while the previous enabled context continues to fence requests. The transaction-scoped `stage_materialization05` and `enable_schema05` hooks admit the persisted desired/previous pair. The transfer owner must prove complete coverage before enabling; preparing Model DDL alone does not complete the transfer or alter S/B/C.

Batch assignment and acknowledgement use the same immediate transaction boundary as Model replay. An acknowledgement stores all exact member outcomes, rolls back rejected ownership and dependent work, and advances lastAck atomically. Accepted work remains durable until coverage and every required target are satisfied. Settlement retains accepted companions in their original local order, replays later direct work, and keeps typed results after operation cleanup. Call identity and completion are projections of the queue, with no second completion table.

Authoritative base and historical evidence are distinct from current protection. Direct writes and deletes release current protection, including tombstones, while keeping historical Stream evidence. Pending optimism keeps protection. Historical evidence prevents stale delivery or old private fallback from restoring authority that a newer statement retired. Production replay and watch filtering use canonical tables directly. No `axton_client`, `axton_mutation` or `axton_mutation_operation` compatibility views, divergence bridge trigger or provisional same-format ALTER upgrade is installed. A missing required layout is refused rather than patched into another format.

The protocol 5 SQLite integration tests cover reopen, faulted commits, abrupt process exit, exact request restoration, unsupported-file admission, accepted/rejected replay, current-marker release and explicit desired-context transaction completion. Server execution deduplication and complete delivery transfer proofs belong to their protocol owners.

Delivery apply exposes coarse timing spans for identity bookkeeping, authority
pre-clear/install, settlement reconciliation and held projection rebuild. Its
SQLite commit remains inside the atomic apply boundary. The
[client encoding experiment](../../../../../integration/performance/baselines/2026-10-28-client-encoding/README.md)
records a client-only rebuild comparison and the measured phase boundaries.
